# XPath Agent visual system

<!-- impeccable:design-schema 1 -->

## Direction

**Jet-age ticket wallet** translated into a browser workbench. XPath Agent should feel like a precise, official document that makes each inspection step accountable without turning the interface into a paper prop.

## Mode

Operate. The task is to select a live DOM element, review evidence, compare validated locators, and export test code.

## World rules

- **Palette:** carrier navy for the shell and primary structure; warm coupon-stock ivory for the workspace; signal red for actions, selected states, and invalid/void states; carbon purple for code and measurement accents; amber only for warnings.
- **Type:** compact official sans for navigation and labels; tabular monospace only for selectors, counts, and captured values.
- **Density:** crisp, information-dense panels with ruled separators and generous enough spacing for fast scanning.
- **Signature move:** every meaningful state reads like a stamp or coupon status: current, validated, needs revalidation, selected, and void/error states remain visible rather than disappearing.
- **Controls:** standard web buttons, inputs, selects, disclosures, and dialogs. World expression must never replace familiar controls.

## Surface contract

- The first viewport must expose the workflow, current page context, primary selection action, and the next required step.
- Evidence and validation must visually outrank optional AI assistance.
- Stale evidence must be unmistakable and block export until revalidation.
- Preserve the existing product terminology, behavior, permissions model, and logo asset.
- Responsive layouts keep the workflow usable in a narrow Chrome side panel.

## Quality bar

Aligned grid, deliberate type scale, accessible contrast, visible keyboard focus, compact but breathable spacing, and clear empty/error/disabled states. No gradients, decorative glass, or UI that imitates a physical ticket literally.
